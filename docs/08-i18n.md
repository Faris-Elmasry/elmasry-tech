# 08 — Internationalization (EN / AR)

## Mechanics
- Locales: `en` (default), `ar` — `src/i18n/routing.ts`; `request.ts` loads `messages/{locale}.json`.
- Middleware runs `next-intl/middleware` for locale prefix handling; `[locale]/layout.tsx` sets `dir="rtl"` on a wrapper `<div>` for Arabic.
- Components use `useTranslations("<namespace>")` for message keys, and inline `isAr ? … : …` ternaries or `*_ar` fields for everything else.
- `useUIStore` also has a `locale` field and `setLocale` (sets `html lang/dir`) but it isn't used by the routing — locale truth is the URL.

## Message namespaces (`messages/en.json` ≡ `ar.json`, 101 lines each, same keys)
`nav` · `hero` (title1/title2 split for gradient, stats, trust) · `sections` (titles/subtitles for services, portfolio, testimonials, about, cta) · `contact` · `common` · `about` (story, skills title, values, CV) · `services_page` (titles, pricing note, FAQ title) · `footer` · `admin` (labels defined but admin UI is hard-coded English).

## Where text is NOT in the message files (hard-coded bilingual objects/ternaries)
| File | What |
|---|---|
| `[locale]/page.tsx` | fallback hero/services/projects/testimonials (`_en`/`_ar`) |
| `[locale]/services/page.tsx` | services, features, pricing, process, FAQ |
| `[locale]/about/page.tsx` | timeline titles, "Experience", Cairo, CV note |
| `[locale]/contact/page.tsx` | service option labels, error messages, "Let's Start a Project" card |
| `[locale]/portfolio/*` | headings, "projects", button labels |
| `components/layout/Footer.tsx` | service links |
| `components/sections/*` | many CTA labels, skill chips |
| `lib/validators.ts` | validation messages (English only) |
| `error.tsx`, `not-found.tsx`, `loading.tsx` | English only |
| Admin (all pages) | English only (admin data fields are bilingual) |

## Known i18n issues
1. Root `<html lang="en" dir>` never changes → screen readers/browsers see Arabic pages as English LTR at the document level (only the inner div has `dir`). `useUIStore.setLocale` would fix it but isn't called.
2. No Arabic font loaded (see design system).
3. `middleware.ts` and `auth.ts` hard-code `/en/admin/login` as sign-in page, and several links (`error`, `not-found`, admin dashboard links) point to `/en`.
4. Arabic copy mixes MSA and Egyptian dialect (e.g. "شوف الأعمال" vs "شاهد أعمالي"); decide one voice for the company.
5. `messages` carry both old niche copy (none currently in `hero`/`about`) and new copy; DB seed still carries niche copy.
6. `useParams()`-based locale reads default to `"en"` if missing.
7. Footer copyright is a static "© 2025".
8. Pricing numbers/currency (EGP) are not localized for Arabic numerals/format.
